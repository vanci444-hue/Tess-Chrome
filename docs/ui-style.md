# Tess-Chrome 界面设计

## 设计目标与判断

销售在客户离店后，用一次简短复盘形成可以带走的决策材料。侧栏突出当前客户、输入和下一步；Report 突出正在比较的方案、已有判断和仍需确认的问题。沿用用户确定的 Tesla / ChatGPT 简洁克制风格，不增加营销大字、渐变底、发光图标、雷达评分或购买意愿分数。

- 侧栏只有一个主视图：客户列表、建档、客户对话、历史报告逐层切换。客户列表不是常驻第二侧栏。
- 对话顶部固定身份和返回入口，中间消息独立滚动，底部输入区固定在容器内；长消息不挤掉输入。
- 录音是输入方式。字幕先进入输入区，停止不发送；发送后才出现销售消息和整理结果。
- 审核阶段在消息流内展示结论和编辑入口，以“确认并生成链接”为主操作；普通发送仍属于输入区，不与发布混为一谈。
- 完整 Report 在新标签页独立展示。首屏先回答三问，再展开数字与细节。所有图表由同一组示例数据计算。
- 原型使用明确标注的模拟采集、转写和整理，不申请麦克风、不访问业务服务、不伪装真实联调成功。原型工具条位于产品界面外。左侧只放原型说明和真实 Tesla 配置器链接，不制作模拟 Tesla 网站；正式 Capture 必须读取真实官网当前状态。

## 全局视觉系统

| 名称 | 值 | 用途 |
|---|---|---|
| Text / Muted | #171a20 / #62666d | 正文、辅助信息 |
| Background / Surface | #ffffff / #f5f6f7 | 页面、分组与用户气泡 |
| Border | #e4e6e8 | 轻边界，不给每段文字套卡 |
| Action | #20242b | 主要按钮，白字 |
| Accent | #3e6ae1 | 仅重点图表与焦点，不作大面积背景 |
| Success | #397b61 | 已确认、可发布；同时写状态文字 |
| Warning | #966323 / #faf5ea | 待确认、部分缺失 |
| Error | #ac3e3e | 阻断、输入错误；同时提供恢复动作 |

字体使用系统 `Inter, -apple-system, BlinkMacSystemFont, Segoe UI, PingFang SC, Microsoft YaHei, sans-serif`，无外部字体依赖。中文正文侧栏14px/1.65，辅助12px/1.55，页标题22px/1.3；Report正文15px/1.75，主标题44px/1.15，章节26px/1.3，关键金额32px，数字使用tabular-nums。Report窄于1100px时主标题36px。

间距采用4、8、12、16、24、32、48、64px。侧栏内边距20px，360px时16px；按钮最小高度38px，输入44px。小按钮8px圆角，输入和功能卡12px，用户气泡16px。Report最大宽1120px，两列模块间距32px，章节间距64px；不足900px改一列（超出MVP手机承诺，仅防止电脑窄窗溢出）。

仅侧栏外壳有轻阴影，卡片以边界和间距分组。悬停改变底色，焦点2px Accent轮廓。过渡120ms；尊重reduced-motion。加载展示文字步骤，不展示伪百分比或模型思维链。

## 共用组件

| 组件 | 表现 | 状态与操作 |
|---|---|---|
| 客户行 | 称呼优先、遮罩联系方式其次、最近会话提示 | 整行进入客户，长称呼换行，不显示完整报告 |
| 导航栏 | 返回、客户称呼、历史报告入口 | 当前客户始终可辨认；切换恢复本会话草稿 |
| 销售身份 | Alex头像缩写与Demo文字 | 只展示，无登录退出操作 |
| 对话 | Agent正文直接排版；销售浅灰气泡 | 保留原文，长文本换行，不用固定高度裁切 |
| Capture卡 | A/B标签、车型版本、价格、移除 | 原型标“模拟快照”，最多3份，第四次显示明确提示 |
| 输入区 | 多行文本、录音/停止、发送 | 空白禁用发送；原型“演示转写”；录音与发送分开 |
| 确认卡 | 月供目标、区域、试驾版本、来源说明 | 疑点突出，确认后继续；未知区域不强制填满 |
| 运行摘要 | 逐条文字状态 | 原型持续标模拟，失败展示受影响模块与继续方式 |
| 审核卡 | 首屏三问、可编辑总结、预览与发布 | 缺少有效候选/核心冲突阻止发布；辅助缺失可发布 |
| Report卡 | 名称、时间、打开报告 | 成功发布后才出现；历史入口引用同一个记录 |
| 图表 | 同单位横条、月供预算线、能源累计曲线 | 标注数值、单位、假设；不混合量纲、不画伪雷达 |
| 静态业务按钮 | 浅灰按钮和“演示”说明 | 不触发真实聊天、预约或分享；地图外链明确例外 |

## 页面与状态

### P01 到店前工作台（插件首页）

依据 REQ-008 / AC-022、039。刚打开不是客户名单。顶栏 Tess 与 Alex。一条「用户列表」进入暂缓设计的名单页。主区 CRM 粘贴；提交后进入确认资料。底部仅 Demo 的「复制演示 CRM」。刷新 Demo 靠侧栏右上、对准 Chrome pin 一侧（无法写入浏览器标题栏）。空态提交不可用；复制成功短反馈。

### P01b 用户列表（暂缓）

今日到店优先、几点来等尚未设计。现仅保留可返回的名单能力，不作为首页，不作为本轮视觉重点。

### P02 确认客户资料

依据 REQ-008 / AC-022。首页提交后进入。不展示称呼/手机/邮箱表单，也不再二次粘贴 CRM。预约试驾用 call out 高亮（时间、门店、默认 Model Y）。其余重点信息列表展示。主操作「确认」。本轮 Demo 不演示联系方式查重（产品方案仍保留 AC-023）。无粘贴内容时返回首页。

### P03 客户对话

依据 REQ-001—005、008。会话页先只保留 Capture 与底部输入。不展示纠正称呼、聊天空态、准备报告与 Mock 跟进。已有预约则不提供新建试驾。输入框单行起、随内容增高；麦克风图标在发送钮左侧。

示例主路径：Evan有两个模拟候选 → 点击“演示转写”逐步显示一段家庭用车复盘 → 停止后仍在输入框 → 手动发送 → 核对月供与区域 → 确认并准备报告 → 模拟工具结果 → 审核卡 → 发布 → Report卡。销售也可直接文字输入。

原型仅模拟整理，真实用户输入保留在消息中；结构化字段需确认，报告称呼、预算、区域、审核总结与当前记录一致。不将未知字段猜成确定事实。

录音中切换需选择结束并保留文字或放弃本段；未发送文字按会话保存。失败演示覆盖采集失败、转写中断、地图失败、预算冲突。地图失败允许部分报告；预算冲突需确认，不能假成功。新会话不复制旧预算和快照。

### P04 审核状态（P03内）

依据 REQ-006 / AC-016、030—033。直接显示“现在比较什么 / 已经明确什么 / 还需确认什么”，附完整预览入口。可编辑总结；预算及区域修改后需要重新准备，旧稿标为待更新。图表数字与官方快照不直接编辑。

成功发布保存不可变原型快照，生成唯一报告链接和卡片；连点不重复创建。此后再生成新稿产生新链接，旧链接不变。持久化失败应保留输入并显示错误，不能显示成功卡片。

### P05 历史报告

依据 REQ-006、008 / AC-024、031、040—042。顶部返回当前客户对话；按时间列出该客户跨会话已发布报告，含日期、标题、候选数、打开链接。无记录显示空状态与返回复盘入口；不展示未发布草稿，不增加版本对比。

### P06 桌面 Report

依据 REQ-006 / AC-016—019、031—033、038、043。独立白底页面，Tess品牌、报告日期和模拟标记；称呼与一句总结；首屏三问；车辆视觉及候选对比；金融预算图、充电地图和列表、能源成本、家庭关注点、Alex联系卡、来源。

车辆图使用Tesla页面公开图片作为视觉参考，标明不代表所选配置；加载失败保留中性车型说明。地图为原型布局示意，不能冒充真实高德结果；外部高德搜索链接真实构造。正式实现替换真实采集/地图图像。

示例价格A321500元、B288500元、共同首付81500元、60期0息，月供分别4000/3450元；均为金融演示数据，不是当前官方报价。能源场景年20000km、电耗15kWh/100km、电价1.2元、油耗8L/100km、油价8元，五年仅能源差额46000元。数值由同一数据模型确定性计算，预算改变后图表同步。

缺地图时保留失败说明及已确认区域；缺第二候选不画双车对比。Report内部业务按钮禁用并解释“演示”，高德入口正常新标签打开；手机号、邮箱和销售复盘原文不进入报告。

### P07 模拟后续动态（P03内）

依据 REQ-007 / AC-020—021、034。显式加载模拟互动后展示产品相关摘要与建议下一步，例如“家人继续关注后排长途体验”。标明“已提供信息，待客户确认”，不伪造已解决或购买意愿分数，不展示家庭私人对话。
