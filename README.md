# Tess-Chrome

用于 Tesla 中国 Model Y 试驾后复盘与跟进的销售侧 Chrome Side Panel Demo。销售先确认客户，再抓取官网当前选配、语音或文字补充信息，确认关键疑点，审核并生成这台电脑可打开的 Report 链接。

**当前交付为本机可运行实现，并未完成全部真实场景验收。** 真实官网 Capture 已独立验证；本地代码、音频协议、确定性计算和正式 HTTP 持久化链路已分阶段通过。本地 `/api/health` 中 llm/asr/maps 为 configured（字段已填），**密钥已配置≠能力已验**。T-008 独立复验 v4.0 仍为 **FAIL**（AC-020 发布后跟进）；跟进修复已冻结，**待独立 Tester，不能写成 T-008 已通过**。T-010 仍为 **BLOCKED**，未通过。T-007 只是本地接口/契约阶段 PASS，**不能当成完整 UI 通过**。没有切换成 Mock Tesla 官网。

## 本机启动

环境：macOS、Google Chrome、Node.js 24+、npm、Python 3.12。依赖安装在本项目 `.venv` 与 `frontend/node_modules`；使用仓库内 `pycore/`，不安装外部同名 PyCore 包。

在项目根目录运行：

```bash
scripts/build-demo.sh
scripts/run-demo.sh
```

或在完成构建后双击 [启动Tess.command](启动Tess.command)。保持启动终端开启；`Ctrl+C` 结束该终端启动的服务。启动器遇到端口占用会提示并退出，不会结束已有服务。

- 正式本机入口：`http://127.0.0.1:8099/`。交接时该服务已运行；已启动时直接使用，勿重复启动。
- 全新环境需先点击“新增客户”，程序不自动塞入业务成功样本。本机已有本轮验收创建的 QA 客户与会话；这些是测试记录，不是真实客户或成交证据，不要为演示清空现有数据。
- 默认持久化位置为 `backend/data/tess-chrome.db` 与 `backend/data/uploads/`，服务重启保留数据。不要为演示重置或删除已有数据。
- 报告地址为 `http://127.0.0.1:8099/reports/{report_id}`。它只供演示电脑访问，未部署公网，不能直接发给其他电脑或手机访问。

## 安装正式 Chrome 插件

1. 构建后，在 Chrome 打开 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本项目的 **`frontend/dist`**。
3. 检查扩展 ID 为 **`ejbpocfjkdofijfgehnnhdnnhigkekdn`**。正式公开公钥固定 ID，后端允许来源必须与之相同；旧 Capture spike 的 ID 不替代正式 ID。
4. 打开 [Tesla 中国 Model Y 配置器](https://www.tesla.cn/modely/design#overview)，点击 Tess 扩展按钮打开右侧栏。
5. 先新增/选择客户与本次试驾会话，再完成官网选配并点击 Capture。金融面板未展开时金融字段会缺失，可展开后重新抓取。

当前只支持该中国区 Model Y 页面，不支持其他车型/市场。最多保留三个候选，新增前可明确移除一个。官网结构变动或页面仍在更新会显示缺失/不稳定，不会自动用 Mock 数据冒充成功。

**正式插件已完成实际安装与局部交互验证。** 2026-09-20 T010 补验确认上述固定 ID，完成 SidePanel → 建档/会话 → 真实官网 Capture → 本地持久化；新旧候选共存、三候选上限、软查重及缺配置提示已实操。完整真实报告链路、麦克风、指定宽度和部分交互仍未验，T010 总结果保持 BLOCKED。

## 配置模型、实时 ASR 和地图

空模板为 [backend/.env.example](backend/.env.example)，构建/启动脚本仅在 `backend/.env` 不存在时复制模板，不覆盖已有配置。由用户在 **`backend/.env`** 填入授权的真实凭证；不要把密钥放进 README、导航、前端变量、截图或仓库。

| 能力 | 需要配置的字段 | 当前边界 |
|---|---|---|
| 百炼大模型 | `BAILIAN_BASE_URL`、`BAILIAN_API_KEY`、`LLM_MODEL` | 基地址应为账户对应的兼容接口根地址；适配器追加 `/chat/completions`。源码默认模型 `qwen3.7-plus`，实际账户权限与调用效果未验。 |
| 百炼实时 ASR | `BAILIAN_API_KEY`、`BAILIAN_ASR_WS_URL`、`ASR_MODEL` | 使用账户支持的 WSS 端点；适配器追加 model 参数。默认 `qwen3-asr-flash-realtime`。真实麦克风与供应商仍需验。 |
| 高德 Web Service | `AMAP_WEB_SERVICE_KEY` | 查询区域、周边充电 POI、路线和静态图，须具备相应服务权限与额度。 |

其余工程参数保留模板默认值。正式启动器要求 `HOST=127.0.0.1`、`PORT=8099`、`REPORT_ORIGIN=http://127.0.0.1:8099`，以及与正式插件一致的 `ALLOWED_EXTENSION_ORIGIN`。修改配置后停止自己启动的服务再重启，不去结束不明进程。

编排器已用 `/api/health` 证实 llm/asr/maps 均为 `configured`。本地配置字段已填；**configured / 密钥已配置 ≠ 真实能力已验**。T-008 独立复验 v4.0 仍为 **FAIL**：AC-013 草稿收口已独立证实，但 **AC-020 发布后跟进 FAIL**（充电 fixture `INVALID_MODEL_OUTPUT`，预算 fixture 空 brief）；真麦 UI / Side Panel 与返回快照仍未独立验。跟进修复已冻结，**待独立 Tester 复验，不能写成 T-008 已通过**。缺配置或调用失败时仍应明确提示，已提交文字仍保留，不返回假字幕、假地图或固定成功报告。`/api/health` 只检查配置是否存在和数据库就绪。

前端只需本机服务地址，模板为 [frontend/.env.example](frontend/.env.example)，**不含任何供应商密钥**。开发预览使用 Vite 5199 与后端8099；正式演示使用已构建的8099同域页面与插件。

## 显式 Mock 界面预览

只想查看界面与契约交互时，在同一台电脑用 Chrome 打开：

```text
http://127.0.0.1:8099/?mock=1#/
```

这是带 Mock 标识的前端本地契约预览，与真实后端客户数据隔离。初次也没有客户，需手动新建；“Mock Capture”、金融与能源演示数据仅为契约样本。该模式不启用真实录音，也不证明官网抓取、真实模型或高德调用成功。正式构建默认真实模式，Chrome 扩展不通过此查询参数开启 Mock。不要把两种模式混作同一条验收证据。

## 已实现范围与限制

- Alex 为模拟已登录销售身份，没有登录/注册流程。客户称呼与至少一种联系方式必填；相同联系方式软提示，不自动合并；同一客户可以多次试驾。
- 真官网选配快照不可变；销售可以标记偏好或移除候选。实际试驾车型另行确认，不从购车候选推断。
- ASR 采用本地 AudioWorklet 与 16kHz 单声道 PCM16LE；实时字幕可纠正，**手动点发送**才进入 Agent。原音不落盘。
- Agent 按需选择白名单工具并读取观察结果；默认6次模型调用、10次工具调用、180秒整轮上限。关键疑点停等销售，不自动发布或联系客户。
- Tesla CRM/内部车型金融与活动能力未接入真实内部系统。金融产品规则标 **Mock**；能源估算标 **Estimate**，只算能源，不是整车总持有成本。官方知识是审核条目的有限 topic 查询，没有通用向量 RAG。
- 审核可改纯措辞；含数字的完整事实句不可直接修改。预算/配置等变化需更新输入并重新生成。发布形成固定快照，不提供版本比较/回滚。
- Report 在桌面查看，Ask Tess、分享、联系与预约等业务按钮均为静态 Prototype；地图及“在高德继续搜索”是实际外链例外。无可信车辆图片时显示明确中性占位。
- 后续家庭互动为显式 Mock 事件，不能根据浏览活跃度推断购买意愿，也不能把“给了资料”写成“顾虑已解决”。

## 刷新页面功能导航

在项目根目录执行：

```bash
python3 scripts/build-project-console.py --strict
```

输入 [docs/project-map.json](docs/project-map.json)，输出 [docs/project-console.html](docs/project-console.html)。仅使用 Python 标准库，静态读取清单中的源码，不导入业务模块，不读取 `.env`、数据库、日志或客户上传内容，也不启动应用。

- 正常来源指纹一致：退出0。
- 来源变化、缺失或解析失败：仍生成带“待复核”提示的页面，`--strict` 退出2；不自动更新 `reviewed_sha256`。
- 导航 JSON 本身损坏、结构/引用无效：生成明确的错误页面并退出1，不继续显示旧的“已核对”内容。
- 源码修改后，由维护者定向重读受影响功能，修改流程/字段/算法说明，再手动更新对应来源的 `reviewed_sha256` 和核对日期。不能只改时间或盲目重算指纹来假装复核。
- `--root`、`--map`、`--output` 支持临时目录的隔离降级测试，不需要修改真实业务文件。复制路径若受浏览器权限限制，页面会显示并选中可手动复制的路径。

本轮是 T-008 跟进修复冻结后的导航重生：哈希与 `reviewed_sha256` 不一致的来源只标待复核，**不把当前盘上哈希改成「源码已核对」**。当前刷新做生成器隔离与 `--strict` 自验，不冒充新一轮浏览器或 T-008/T-010 业务验收通过。
